# Progress Report 01 — 2026-10-16

## Summary

SD Erlang 19.3 (the historical build) now runs locally: three BEAM nodes, each in
its own podman container. A small demo app passes all **10 s_group checks**. The
same three nodes on stock OTP show the transitive full mesh that s_groups prevent.

## How to run

```bash
bin/sd-demo all          # start 3 nodes, run the 10 checks, then the stock-OTP comparison
bin/sd-demo status       # each node's groups and connections
bin/sd-demo shell gpu1   # Erlang shell attached to a node
bin/sd-demo down         # stop and clean up
```

From scratch: `bin/sd-archive` (fetch and pin sources), then `bin/sd-build-historical` (build).

## Demo topology and results

```text
            local_ai                 external_ai
   gpu1 ───────────────── gateway ───────────────── connector
 worker_pool                                       worker_pool
```

| Check | Result |
|---|---|
| Overlapping groups: each node sees only its own groups; gateway is in both | PASS |
| No transitive connection: gpu1 and connector both connect to gateway, but never to each other | PASS |
| Group-scoped names: `worker_pool` resolves to gpu1 in `local_ai` and to connector in `external_ai`, and is absent from plain `global` | PASS |
| Routing: `s_group:send/3` reaches the right worker | PASS |
| Registration limits: a node can't register in a group it isn't in | PASS |
| `add_nodes/2`: gpu1 joins `external_ai` dynamically | PASS |
| `remove_nodes/2`: membership settles on both sides | PASS |
| `new_s_group/2` + `delete_s_group/1` | PASS |
| Crash: killing connector leaves `local_ai` working; the container restarts and its worker re-registers | PASS |

**The comparison.** I also built the stock OTP commit the SD patch sits on
(`5da9e0ab`), so the two builds differ only by the patch. On SD, gpu1 is connected
only to `[gateway]` for the whole observation window. On stock OTP, gpu1 is
connected to `[gateway, connector]` about 200 ms after the gateway connects to both.

## Practices from the handoff guide

- Everything is pinned by commit SHA, never by branch name (`manifests/historical-sources.yml`).
- Sources are archived as git bundles, with SHA-256 hashes recorded (`manifests/SHA256SUMS`).
- The build uses the guide's digest-pinned Ubuntu 14.04 image, with its full package
  list frozen into the repo (`manifests/trusty-build-lock-arm64/`).
- The build reads only from the local bundle; it never clones from the internet.
- Built image IDs are recorded (`manifests/*.image-id`).
- The nodes run on an `--internal` podman network with no internet access.
- The Erlang cookie is generated per run and passed as a podman secret, so it is
  never on a command line or in the repo.
- Every check is either "this must never happen" (watched over a window) or "this
  must settle by a deadline".
- The status of each verification method is recorded honestly in
  `manifests/verification-status.yml`.

## Findings that affect the plan

1. **The "19.3" branch isn't built on OTP 19.3.** `19.3-rebased` (`0fdfcf28`) is a
   single commit, "Add s_group functionality", on top of upstream `master` from
   2017-03-31 (`5da9e0ab`), which reports itself as OTP `20.0-rc0`. The guide's
   six-file diff against the `OTP-19.3` tag picks up about 25 lines of unrelated
   upstream changes. Both patches are kept in `patches/reference/`; the exact
   single-commit patch (`sd-19.3-s_group-commit.patch`) is the reliable one. The
   commit also touches `lib/kernel/src/Makefile` and the bootstrap `kernel.app`, in
   addition to Glasgow's six files.
2. **The original QuickCheck model isn't public.** The D3.3 `eqc_statem` model is not
   on any branch of `release-project/otp` (17.4/19.2/19.3-rebased, dev, repair,
   sd-erlang-tutorial, master). The demo checks are not that model.
3. **Removing a node from a group doesn't close the connection.** In 19.3,
   `s_group:disconnect_nodes/1` notifies `global` and the peer's s_group but never
   calls `erlang:disconnect_node/1`. The node leaves the group's namespace, but a
   network link opened while it was a member stays up. The demo reports this but
   does not assert it either way.
4. **A restarted node can reuse its old process IDs.** OTP 20's 2-bit node creation
   restarts at 1 under a fresh epmd, so the restarted worker's pid compares *equal*
   to the old one. The crash check uses node uptime instead.
5. **It builds natively on arm64.** The guide's pinned Ubuntu image is a manifest
   list that includes an arm64 version, so the build runs natively on Apple Silicon.
   The amd64 build the guide lists as the reference isn't done yet.

## Deviations from the guide

- **Percept2 left out:** it is profiling tooling from the RELEASE project, not part of s_group.
- **`--without-wx` dropped:** it broke the `debugger` build (unknown `wx_object`
  behaviour, and warnings are treated as errors). Glasgow's plain `configure` is used instead.
- **Podman instead of Docker**, as requested.
