# Progress Report 04: the OTP 29.1.2 kernel port, milestone 1 green

Goal: SD Erlang as a small, rebase-friendly patch set on stock OTP 29.1.2
(design B), following every recorded decision, with each milestone gated by
the verification stack.

## What exists now

- `patches/otp29/0001-…patch`: one patch against upstream `lib/kernel` of
  `OTP-29.1.2`, +690/−10 lines, 600 of them the new `s_group.erl`. Upstream
  files touched:
  - `global_group.erl`: the five seam functions dispatch to `s_group`;
  - `global.erl`: the R-API-5 guard;
  - `kernel.erl` / `kernel.app.src`: start `s_group`.

  `global`'s sync, locker and partition-prevention code is unchanged.
  Design: `port/KERNEL_PORT.md`.
- `bin/sd-port-tree` (patch-authoring tree), `bin/sd-build-port` (image
  `localhost/sd-erlang:29.1.2-sd-kernel`, built from the pinned upstream image
  with its own compiler), `bin/sd-gate` (the milestone gate).

The central mechanism reuses what upstream already has:
- `group_configured()` true makes `global` sync only after `group_nodeup`, so
  `s_group` decides that `global`'s namespace is the free namespace;
- `publish/2` decides link visibility per connection, using 19.3's rule;
- `connect_all` stays at its default, so free nodes mesh and are protected
  by partition prevention exactly as in stock OTP.

## Found and fixed on the way (each kept as a regression case)

1. **A lost link was treated as process death.** D-1's re-dial disconnects a
   hidden link. The monitor's `'DOWN'` with reason `noconnection` was then
   broadcast as `pid_down`, which deleted a live name on every member.
   Found by L1 at test 157.
2. **The provider answer changed under `global`.** `s_group` removed its free
   peer on `nodedown` before `global` asked `participant/1` for that same
   event, so partition prevention never fired. Found by L5 (seq 16:
   19/20 → 20/20).
3. **Harness, not kernel:** L2's port observer assumed
   `global:registered_names/0` returns free names. On members, the kernel now
   returns the 19.3 `{Group, Name}` pairs (core 25/30 → 30/30).

## Model checking notes

- `SGroupPOPHeal`: plain per-group logical removal fails (a stale report
  after the heal); with incarnations, both invariants hold at one failure on
  both topologies.
- The two-failure check was stopped at **22.6M distinct states with no
  violation**. That's incomplete, not a proof; plain logical fails at 135k.
- My first heal model, without merge semantics, produced a false
  counterexample (see `spec/tla/README.md`).
