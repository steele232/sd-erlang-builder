# Progress Report 06: the OTP 29.1.2 kernel port is complete (milestones 4 and 5)

The goal was the SD Erlang kernel port on stock OTP 29.1.2 (design B), as a
small, rebase-friendly patch set that follows every recorded decision and is
gated at each milestone by the verification stack. It is **done**: final gate
and acceptance results are below.

## The deliverable

`patches/otp29/`: 9 patches against upstream `OTP-29.1.2` `lib/kernel`,
+1088/−10 lines. Upstream files touched:

| file | change |
|---|---|
| `global_group.erl` | the five seam functions dispatch to `s_group` while it is the topology provider (+45) |
| `global.erl` | R-API-5 guard on the free-name API for group members (+40) |
| `kernel.erl`, `kernel.app.src` | start `s_group` (+12) |
| `s_group.erl` | new: API, topology provider, group namespaces, POP1 + merge, `-rsconfig`, optional trace |

`global`'s sync, locker and partition-prevention code is untouched.

- **Build:** `bin/sd-build-port` produces `localhost/sd-erlang:29.1.2-sd-kernel`
  from the pinned `erlang:29.1.2` image, using its own compiler.
- **Design:** `port/KERNEL_PORT.md`.
- **Plan and status:** `port/MILESTONES.md`.
- **Rebase check:** `bin/sd-port-rebase-check`. All patches apply cleanly to
  OTP-29.0.6, 29.1, 29.1.2 and upstream `master`. That's *applies*, not
  *builds and tests*: there is no OTP master image to build against yet, and
  29.1.2 is the newest release.

**Decisions implemented:** D-1 (pre-existing links become visible, also for
the free namespace), D-2, D-3/D-4, D-6 (GG1), U1, POP1, RC1
(`s_group:connect_node/1`). M1 is deferred by the user.

## Milestones 4 and 5

**Milestone 4, hardening:**
- `-rsconfig` persists every membership change atomically (R-PERS-1):
  3/3 recoveries at 0 ms between changes, where 19.3 managed 0/3;
- H2 / R-HID-1 probe, shown to detect 19.3's divergence: conforms on the port;
- `bin/sd-pop` asserts that partition prevention never cuts a link.

**Milestone 5, acceptance** found six real defects. Each was fixed with a
regression case or probe, and each run after a fix starts from scratch:

| Found by | Defect | Fix |
|---|---|---|
| acceptance L1 (test 94) | a hidden link between two nodes that later both become free was never upgraded, so one free node stayed out of the free mesh | 0004: re-dial hidden links to free nodes on becoming free (`l1-sdk-freedhidden`) |
| gate L1 (test 194) | our own D-1 re-dial looked like a node failure: some replicas deleted live names, causing divergence | 0005: mark deliberate re-dials; re-monitor after reconnect (`l1-sdk-redial`) |
| demo3 crash step | my first fix (deferred deletion) let a restarted node's dead pid linger and be merged back | 0006: names are dropped by **liveness**, consistently across the partition; merges never carry dead pids |
| L2 visibility triage (seq 30) | a link between fellow members stayed hidden (re-dial raced the install handshake) | 0007: D-1 made eventual (tick re-dial); new L1 check **C5**, validated on 19.3 (6/20) |
| corrected O5 probe (1/20) | a registration computed its target partition before taking the lock; a merge in between let it skip a newly merged member, permanently | 0009: name operations and merges read the partition **inside** the lock (O5: 0/40) |
| image build | `timer:send_interval/2` in `s_group:init/1` deadlocked kernel boot | `erlang:send_after/3` |

Harness defects, each fixed so the tools measure the port and not artifacts:
- the Q2/O5 probes and L2's observer used 19.3-internal functions;
- `campaign_cases` ran at PropEr size 1, i.e. 0–1 commands per case;
- the demo crash check asserted a transient `undefined` instead of P16;
- `sd-accept`'s L2 step compared strictly against one recording instead of
  outcome sets.

Patch 0008 adds an off-by-default event trace (`-s_group_trace`). It
pinpointed the 0009 race in one run.

## What remains outside this goal

Honest caveats:
- the rebase check proves the patches *apply*, not that they build and pass
  on `master`;
- the TLA+ models cover the protocol design, not the connection layer where
  most acceptance defects lived. Next: an `SGroupLinks` model and trace
  validation (the 0008 trace is a start);
- M1 (failure semantics in L1) is deferred by the user;
- Q4 remains an open defect of the 19.3 reference;
- not yet done: packaging (host build, Elixir image), scale and performance
  (we tested 15 nodes; RELEASE used hundreds), and wider fault coverage
  (flapping links, multiple partitions, soak runs).
