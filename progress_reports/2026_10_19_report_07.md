# Progress Report 07: hardening, rebase verification and packaging of the OTP 29.1.2 kernel port

Goal (phases 1–3): rebase verification on a pinned upstream `master`;
failure-mode hardening (connection-layer models, D-7/D-8/D-9, trace
validation, M1, wider fault injection); packaging (host build, release
artifact, Elixir image, usage docs and migration guide). Phase 4,
performance at scale, is deferred by the user.

## Phase 1: rebase verification

`bin/sd-port-release-check REF` (a branch, a tag or a pinned commit sha):
1. builds stock OTP from that upstream snapshot in podman (pinned
   `buildpack-deps:trixie` digest, rebar3 3.27.0 by sha256);
2. applies the series with `git am --3way` and lints the kernel build
   lists;
3. builds the SD image;
4. records the stock L5 reference twice (self-agreement);
5. runs the full gate with that reference;
6. appends the verdict to `manifests/release-checks.yml`.

Pinned master: `9580f21fb60b40c942478cf3dc443791a25717c7` (OTP 30).
Result:
- all 16 patches apply; lint clean; the SD image boots;
- stock L5 self-agreement 20/20;
- **`GATE RESULT: pass`** on OTP 30, every layer below included
  (`manifests/release-checks.yml`).

On the way there, the master check found patch 0010 and the OTP 30
harness build failure.

## Phase 2: failure-mode hardening

**Connection-layer models (`spec/tla/`).** Each has a rule switch. The rule
before a fix must reproduce the defect that fix addressed (`EXPECT:
violation`), and the current rule must pass:

| model | old rule reproduces | current |
|---|---|---|
| `SGroupLockScope` | 0009: registration writes to a partition read before the lock | pass; with anti-entropy, even the old rule converges |
| `SGroupNameGC` | milestone-1 `noconnection` broadcast; pre-0005 local delete on `nodedown`; the first 0006 attempt | liveness-based cleanup passes |
| `SGroupVisibility` | pre-0007 one-shot mesh; pre-0004 no free re-dial; **0004's one-shot free re-dial (new, fixed by 0011)** | both re-dials eventual: pass |
| `SGroupMembership` | a version counter loses one side's changes; 19.3-style restart re-asserting its record overrides a removal | OR-set membership, records as claims: pass |
| `SGroupMergeLock` (liveness) | pre-0015: a retrying merge holding the lock across a cut starves registrations | dial outside the lock: pass |

`bin/sd-tla`: all 40 configs give the expected result (23 at report 06).

**D-7, D-8, D-9 (patch 0012).**
- Membership is an observed-remove set per group incarnation, and deleted
  groups leave tombstones.
- The `-rsconfig` record carries both, and on restart it is a claim that
  the current members resolve.
- Anti-entropy compares hashes with a random in-sync peer every 5 s
  (`s_group_anti_entropy_ms`) and repairs a mismatch by merging.
- Probe `sd_pbt_rejoin`: a node removed while down (rsconfig and static
  config) and a group deleted while down: all pass.

**Trace validation.**
- With `-s_group_trace`, `bin/sd-pop` merges g1's member traces and emits
  a TLA+ module that replays them.
- TLC checks `InSyncAgree` in every state with no operation in flight, and
  that the whole trace was replayed.
- Both POP orders validate: 43 events each, every state checked.
- This is an invariant checked along real executions, not a refinement
  proof.

**M1 in L1.**
- `sd_model:node_down_up/2`: membership is unchanged, the names of the
  node's processes are removed, and the node re-meshes.
- 2 new unit tests (24 pass).
- The statem command `node_down_up` (with `SD_PBT_FAILURES=1`) restarts a
  real node from its `-rsconfig` record.
- 100/100 cases, with `node_down_up` exercised in about 2% of commands.
- An earlier "pass" had not forwarded the flag into the container, so it
  tested nothing. Fixed, and now part of the gate.

**Fault injection (`bin/sd-faults`)**, real iptables cuts and container
restarts on 4 nodes with overlapping groups:
- `flap`: 5 cut/heal cycles with registrations on both sides;
- `twocuts`: two simultaneous partitions across both groups;
- `restart_merge`: a restart during the post-heal merge;
- `coldstart`: the whole cluster down and up from records.

All pass, and they are part of the gate. **Soak:** 30 minutes, 25 rounds
× 4 scenarios = 100/100 converged (`SD_FAULTS_SOAK_MIN=30`).

**Defects found and fixed in this phase**, each with a regression case:

| defect | fix | regression |
|---|---|---|
| OTP 30 deprecation breaks `-Werror` | 0010 | the release check builds on master |
| one-shot free re-dial loses to a handshake that decided before the install | 0011 | `SGroupVisibility_oneshot_free_redial` |
| merge held the group lock while dialling across a cut link: registration starved (33 min) | 0015 | `SGroupMergeLock_old`; `bin/sd-pop` x-first order, now with every step bounded at 5 min |
| `s_group` missing from the kernel Makefile | 0016 | `bin/sd-port-lint` in every build path |

Harness defects, fixed so the tools measure the port:
- the L1 failure mode was never enabled in the container;
- TLC's tmpdir pointed into the sandbox, so trace validation never ran;
- `sd-pop` parsed TLC output with `cut`, which in that script is the
  link-cutting function;
- the OTP 30 harness build failed;
- the gate had no verdict, so an empty layer line went unnoticed. It now
  ends with a computed `GATE RESULT`, and an empty or missing line fails.

## Phase 3: packaging

- **Host build:** `bin/sd-host-build PREFIX`.
  - Official `otp_src_29.1.2.tar.gz` (SHA-256 equal to upstream's
    `SHA256.txt`), `patch -p1`, configure, make, install, boot check.
  - Verified on macOS arm64 (Homebrew OpenSSL), plus a two-node
    group/registration check on the installed runtime.
- **Release artifact:** `bin/sd-release VERSION [--images]`.
  - Writes `dist/sd-erlang-29.1.2-sd-0.1.0/`: patched source tarball,
    patch tarball, kernel overlay for an existing 29.1.2 install, docs,
    `MANIFEST.txt` and `SHA256SUMS`.
  - Images are optional, as gzipped OCI archives.
  - Checked: all checksums verify, and the overlay installed into the
    stock `erlang:29.1.2` image boots with `s_group`.
- **Elixir image:** `bin/sd-build-elixir`.
  - Elixir 1.20.4 (supports OTP 27–29), built from its source tag
    (sha256 pinned) on the SD runtime, giving
    `localhost/sd-elixir:1.20.4-otp29.1.2-sd`.
  - Two-node smoke test (`test/elixir/smoke.exs`): `connect_node` RC1
    semantics, group formation, GenServer under
    `{:via, :s_group, {g, name}}` called from the peer, a duplicate start
    refused, and the `global` guard on members. 10/10 checks pass.
- **Docs:** `docs/USAGE.md` (install forms, concepts, API, via tuples,
  partitions and repair, persistence, knobs, limitations) and
  `docs/MIGRATION.md` (step-by-step from stock OTP and Elixir, the via
  adapter, what assumes a full mesh, libcluster, and the differences from
  19.3).

## Open items

- Phase 4 (performance at scale, Orbit, Partisan comparison) is deferred.
  Every result so far is at up to 15 nodes.
- Known limitations, documented in `docs/USAGE.md`:
  - repair is a union, so an unregister lost to a partition or a crash can
    come back;
  - the `*_external` functions are aliases;
  - there are no membership-change hooks.
- Q4 remains an open defect of the 19.3 reference, not of the port.
