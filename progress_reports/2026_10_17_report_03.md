# Progress Report 03 — 2026-10-17 (evening)

Covers the OTP 29.1.2 bring-up after Report 02: running the whole
verification stack against a real modern implementation, and what that taught
us about both the port and the verification stack itself.

Branch `sd-19.3-reference-demo`; commits 7bb8efc, 3e0adda, 3b65fd7, plus
uncommitted work listed in §6.

## 1. Summary

- **A modern runtime now goes through every layer.** `port/sdx` is a
  library-only prototype of the s_group API on stock OTP 29.1.2. It has no
  kernel changes; the kernel port still waits on decision D-5. Its purpose is
  to give each verification layer a real modern implementation to judge.
- **Each layer found something real.** L3 found a missing name merge, L1
  found missing free-node meshing, and a new probe (P18) found that members
  can use the stock `global` namespace. All are recorded as port requirements.
- **Measured result: a library-only port can't be correct on OTP 29.**
  Stock `global` can satisfy free-node behaviour (S2) or group isolation (S3),
  but not both: `connect_all` is one global switch and the decision has to be
  made per node pair. The kernel hook in design B is therefore *necessary*.
- **The verification stack had two holes, now fixed:** an L1 profiling mode
  that tested near-empty sequences, and L1 never checking link *visibility*
  (P1).

## 2. Modern harness bring-up (commits 7bb8efc, 3e0adda)

- **PropEr 1.5.0 harness for OTP ≥ 22** (`containers/pbt/Containerfile.modern`).
  `bin/sd-pbt` picks the right harness by the runtime's OTP release. Stock
  `erlang:29.1.2` is pinned by digest in `manifests/images.lock`.
- **Code works on OTP 20 and 29 alike.** `sd_compat:safe/1` replaces the
  `catch` that OTP 29 deprecates, and keeps exit reasons intact, so traces from
  both harness generations compare.
- **UD1, stock OTP 20 vs stock 29.1.2 on free nodes: 19/20 identical.** The
  one difference is `prevent_overlapping_partitions`: after a single
  `disconnect_node(n6, n9)`, OTP 29 cuts n6 and n9 off from *everyone*. Under
  s_groups, "n6 not connected to n9" is the normal state, so this is direct
  evidence for D-5. Consequence: a port's L5 reference is stock 29, not 19.3.

## 4. Why a library-only port is ruled out (now measured, not argued)

| Setting | Group isolation (S3/P1) | Free nodes as distributed Erlang (S2, L5) |
|---|---|---|
| `connect_all false` | holds | **1/20**: 29.1.2's `global` never syncs under `connect_all false` (on nodeup it only records the connection id). Upstream documents that `global` is unreliable unless `connect_all` and `prevent_overlapping_partitions` are both on |
| `connect_all true` | **violated**: transitive meshing joins groups (C4 below) | 19/20. The one difference is which of two conflicting pids wins a name, which depends on pid allocation order; a control run is in flight |

`global` reads `connect_all` once at startup, so it can't vary per group. The
question "should `global` sync with, and mesh towards, this node?" must be
answered per node pair, and that is exactly the `global_group` seam (Seam 1).
P18 points the same way on its own. Written up in
`spec/PORT_OTP29_FEASIBILITY.md`, section "Option L".

## 5. Corrections to the verification stack itself

1. **`bin/sd-pbt cases` tested near-empty sequences.** With `numtests 1`
   PropEr generates at size 1. Measured: 0–1 commands per case, versus 0–25 at
   size 25. No documented claim relied on it (`campaign` and every A/B use
   growing sizes). Fixed with `{start_size, 25}`.
2. **L1 never checked visibility (P1).** Its connection check C3 counts hidden
   links, so a fully meshed prototype passed 30/30. New opt-in check **C4**
   (`SD_PBT_VISIBILITY=1`): every visible link must join two nodes that share
   a group, or two free nodes, or be a link the model itself keeps.
   - The first C4 run fired on 19.3 too (1/20). The cause was O1: links kept
     by `remove_nodes/2`, which is registered must_match behaviour. So the
     check now accepts the model's own connections.
   - It also caught a real prototype defect: every member monitored every
     registered pid, which opens a visible link to the pid's node. Fixed:
     monitor only over existing links, and propagate deaths by message and
     nodedown.
3. **`bin/sd-pbt` passes `SD_PBT_NODE_ARGS` through,** so the same image can
   run with different kernel flags. This is how §4 was measured.

So far the verification stack has found **six real defects** in a modern
implementation: missing name merge, missing free mesh, members using the free
namespace (unfixable in a library), visible links from monitors, the join
race, and the S2/S3 incompatibility of a library-only design.

## 7. Where this stops: waiting on decisions

The next real step is the kernel port (design B), and its shape depends on
**D-5** (`prevent_overlapping_partitions` under s_groups). Tonight's results
made it more pressing:
- a port can't avoid hooking `global` (§4);
- upstream says `global` is unreliable unless both `connect_all` and
  `prevent_overlapping_partitions` are on;
- with them on, overlapping groups lose links (UD1, and demo15 above).

D-1…D-4, D-6 and U1 set `port_policy` values that L1/L2 acceptance needs. All
of them are in `spec/DECISIONS.md` with sources. Q4 stays open, but it's a
defect in the historical reference and doesn't block anything.
